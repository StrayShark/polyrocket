## 2. 实现细节

### 2a. Deps (Cargo.toml)

```toml
specta = { version = "=2.0.0-rc.25", features = ["derive"] }
specta-typescript = "0.0.12"
tauri-specta = { version = "=2.0.0-rc.25", features = ["derive", "typescript"] }
```

**踩坑**:
- `specta-typescript` 必须 **直接列在 deps**, 不能省略。tauri-specta 虽然
  bundle 了相同版本 (0.0.12), 但 type identity 不同 — 直接 import
  `specta_typescript::Typescript` 会让 `Builder::export` 的 `LanguageExt`
  bound 不满足。
- `tauri-specta::specta` 不存在。 真正的宏路径是 `specta::specta`。
  来自 tauri-specta README 例子, 我之前的 migration plan 写错了。

### 2b. Command 标注 (pnl.rs)

```rust
#[derive(Debug, Serialize, Deserialize, Type)]  // ← + Type
pub struct DashboardKpis { ... }

#[tauri::command]
#[specta::specta]  // ← + specta macro
pub async fn dashboard_kpis(state: State<'_, AppState>) -> AppResult<DashboardKpis> { ... }
```

**踩坑**:
- `DashboardKpis` 之前只 `Serialize`, codegen 需要 `Deserialize + Type`。
- AppError 不 derive Type, 所以 `collect_commands!` 会 fail 在
  `FunctionResult` trait bound 上。**解决**: bin 内置 codegen-friendly DTO,
  用 `Result<DashboardKpisDto, String>` (String error 满足 trait), Phase 3
  再考虑对 AppError 加 Type 派生。

### 2c. Bin (gen_ts_types.rs)

```rust
use polyrocket_lib::commands;
use specta::Type;
use tauri_specta::{collect_commands, Builder};

#[derive(serde::Serialize, serde::Deserialize, Type)]
struct DashboardKpisDto {
    total_equity_usdc: String,
    open_pnl_usdc: String,
    win_rate_30d: f64,
    brier_score: f64,
    active_signals: i32,  // ← i32 不是 i64 (i64 是 BigInt, 默认禁止导出)
    open_positions: i32,
}

#[tauri::command]
#[specta::specta]
async fn dashboard_kpis_codegen() -> Result<DashboardKpisDto, String> { ... }

fn main() {
    let builder: Builder<tauri::Wry> = Builder::new()
        .commands(collect_commands![dashboard_kpis_codegen]);

    let out_dir = std::path::PathBuf::from(env!("CARGO_MANIFEST_DIR"))
        .parent().unwrap()
        .join("src/types/generated");
    // ...
    builder.export(specta_typescript::Typescript::default(), &out_file)?;
}
```

**踩坑**:
- `Builder::new()` 的 Runtime 推断不到。 必须显式 `Builder<tauri::Wry>`。
- `out_dir` 必须用 `CARGO_MANIFEST_DIR` (绝对路径), 不能用 `../src/...`
  相对路径 (cargo 的 CWD 在 `src-tauri/`, 但 `..` 跳得比预期远)。
- `i64` field 不能默认导出 — specta-typescript 禁止 BigInt-style types
  (避免精度损失)。 Phase 1 用 `i32` 占位, Phase 3 用 `BigInt<i64>`
  wrapper 或 `#[specta(type = BigInt)]` per-field 解决。

### 2d. lib.rs 可见性

```rust
// 之前: mod commands;
// 现在:
#[doc(hidden)]
pub mod commands;
```

**原因**: `collect_commands!` 宏展开时需要 `__cmd__*` (Tauri 生成的)
和 `__specta__fn__*` (specta 生成的) 私有符号。 这些符号是
auto-generated by macro, 不能跨 module 边界 re-export (会找不到)。
最简方案: 整个 `commands` module 设 pub。 Tauri IPC surface 本来
就通过 `invoke_handler!` 公开了 main.rs, 所以可见性变化无安全影响。

## 6. Patterns locked (codegen-specific)

### 6a. BigInt opt-in pattern

For i64/u64 fields, use either:
```rust
use specta_typescript::BigInt;
pub field: BigInt<i64>,
```
OR per-field:
```rust
#[specta(type = BigInt)]
pub field: i64,
```

**polyrocket convention** (i64 → number on wire): need a custom `Type` impl
that overrides the i64 mapping. Phase 3 work item.

### 6b. Error type pattern

For commands returning `Result<T, AppError>`:
- AppError needs `#[derive(Type)]` for the trait bound
- OR use `Result<T, String>` and convert at the bin layer
- OR wrap in a codegen-friendly NewType

Phase 1 = option 3 (NewType). Phase 3 = add `#[derive(Type)]` to AppError.

### 6c. Module visibility for codegen

If `collect_commands!` can't find `__cmd__*` symbols, the simplest fix is
`pub mod commands;` at the lib root. Tauri IPC surface is already
publicly reachable via `invoke_handler!`, so visibility has no security
implication.

### 6d. Output path resolution

Use `CARGO_MANIFEST_DIR` env var, not relative paths from CWD:
```rust
let out_dir = PathBuf::from(env!("CARGO_MANIFEST_DIR"))
    .parent().unwrap()
    .join("src/types/generated");
```

CWD is `src-tauri/` when cargo runs the bin, but `..` jumps are
unreliable (sometimes lands at `<workspace>` not `<project>`).
